# LBRY Hub NG 1.1.0rc1

This community-maintained candidate requires CPython 3.13 on Linux x86-64 with
glibc 2.35 or newer. Use a fresh environment and retain the existing database
directory. The old `lbry-rocksdb` distribution must not coexist with
`lbry-rocksdb-ng`; they install the same module.

The runtime uses the hash-pinned `lbry-rocksdb-ng` 0.8.3 CPython 3.13 wheel.
The underlying RocksDB engine remains 6.25.3. Shared SDK/Hub dependencies and
the production Docker image have been updated for Python 3.13.

Saved SHA-256 state no longer depends on CPython/OpenSSL private memory.
Legacy 120-byte states can be resumed, persisted, reopened and rolled back
without changing the bytes used for database undo checks. The tests include
states written by the old implementation and large bit counters.

Protobuf modules are regenerated from checked-in sources with protobuf 7.36.2.
Captured descriptors and wire vectors verify the existing deployed field
definitions, serialized bytes and unknown-field preservation. JSON-RPC request
completion, batches and disconnects also work with modern asyncio events.
Hub shutdown closes client connections before waiting for listeners, avoiding
the deadlock introduced by newer asyncio server-close behavior.
While the search backend reconnects, claim search returns RPC error `-32001`
(`claim search is temporarily unavailable`). Clients can retry after recovery;
an unavailable backend no longer appears as an internal error or an empty result.

See [the test guide](../testing.md) and
[PR #9](https://github.com/kodxana/lbry-hub-ng/pull/9) for the database,
rebuilt-binding and SDK resolve/session checks. The Docker image also passes
dependency and service-command smoke checks without contacting a blockchain.
No full-size production snapshot or mainnet deployment has been exercised.
Retain a database backup and the prior environment before evaluating this
candidate on production data. No Elasticsearch major-version migration is
included.
